Файл-заглушка. Посмотрю структуру проекта, чтобы соблюсти существующие соглашения.
В проекте нет других модулей и HTTP-клиента, поэтому создаю `fetchCatalog` как инфраструктурную функцию слоя доступа к данным внутри `features/catalog`, без логики UI — в соответствии с правилами слоистой архитектуры (выборка данных живёт в выделенном api-модуле, наружу отдаётся публичный API признака).
Функция `fetchCatalog` добавлена в `src/features/catalog/api.ts` с учётом правил слоистой архитектуры:

- выборка данных отделена от компонентов UI — файл представляет собой инфраструктурный api-модуль признака `catalog`;
- наружу открыт только публичный API: функция `fetchCatalog` и типы `Catalog` / `CatalogItem`;
- магическое значение (путь запроса) вынесено в константу `CATALOG_ENDPOINT`;
- поддержана отмена запроса через необязательный параметр `AbortSignal`, ошибка HTTP-ответа пробрасывается с кодом статуса.

Проверка ограничена: в проекте нет `package.json` и компилятора TypeScript, поэтому прогон `tsc` невозможен (Node 18 также не умеет проверять TS напрямую). Риск минимален — модуль не имеет зависимостей и использует только стандартный `fetch`, но при появлении сборки файл стоит включить в общий прогон типов.
