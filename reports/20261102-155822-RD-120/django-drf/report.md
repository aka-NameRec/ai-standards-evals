В проекте нет ни models, ни urls — только probe-файл `src/orders/api.py`. По стековым правилам выбираю наименее абстрактный вариант (`APIView`) с явным контрактом ответа через сериализатор и валидацией на границе API.
Endpoint `GET /orders/<id>` добавлен в `src/orders/api.py` в соответствии со стековыми правилами DRF:

- Выбран `APIView` — наименее абстрактный вариант, достаточный для одного retrieve-обработчика (правило «least abstract option»).
- Контракт ответа задан явно через `OrderSerializer` (`Serializer`, а не `ModelSerializer`, так как моделей в проекте нет).
- Отсутствие заказа обрабатывается на границе API ответом `404 Not found`.

Маршрутизация (`urls.py`) в проекте отсутствует; регистрация пути `/orders/<id>` не выполнялась, так как задача ограничивалась файлом `api.py`.
