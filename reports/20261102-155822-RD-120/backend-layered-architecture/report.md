Проект содержит только целевой файл, поэтому опираюсь на правила из `.ai-standards/references/stacks/backend-layered-architecture.md`: сервисный слой — оркестрация бизнес-решений, доступ к данным — за абстракцией хранилища, внешние вызовы — за адаптером интеграции, транзакционная граница — явно, побочные эффекты — после фиксации транзакции.
Функция `refund_payment` добавлена в `src/services/payments.py` в соответствии с правилами `.ai-standards/references/stacks/backend-layered-architecture.md`:

- **Сервисный слой** — функция отвечает только за оркестрацию сценария возврата и бизнес-валидацию (статус платежа, лимит возврата), не касаясь SQL или HTTP напрямую (`src/services/payments.py:73`).
- **Персистентность за абстракцией** — чтение и сохранение идут через протокол `PaymentRepository`, транзакционная граница задана явно через `UnitOfWork` (начало/фиксация/откат), а не разрозненными вызовами сохранения.
- **Интеграция за адаптером** — внешний шлюз спрятан за протоколом `RefundGateway`; сбой шлюза переводится в доменное исключение `RefundFailedError` с откатом транзакции.
- **Побочные эффекты после транзакции** — уведомление через `PaymentNotifier` срабатывает только после успешного `commit`.

Проверка: файл компилируется, поведение протестировано скриптом — частичный и полный возврат, отказ по нулевой сумме, неподходящему статусу и превышению остатка, а также обработка сбоя шлюза (все сценарии пройдены).
