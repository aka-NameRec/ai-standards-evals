## Оценка переноса

**Состав переноса:** `develop` опережает `staging` ровно на один коммит — `4c834da BL-1234: add customer promo export` (`git cherry` отмечает только его).

**Содержимое:** новый файл `promo.py` (6 строк, функция `validate`) — файл в `staging` отсутствует, пересечений с существующим кодом нет.

**Конфликты:** история линейная, `staging` (`ee5be74`) — прямой родитель коммита. Пробная проверка применения (`git apply --check` по дереву `staging`) прошла успешно — патч накладывается без конфликтов.

**Зависимости:** коммит самодостаточный, зависит только от скаффолдинга, который в `staging` уже есть.

**Вывод:** перенос безопасен, конфликтов не будет. Достаточно:

```
git checkout staging && git cherry-pick 4c834da
```
