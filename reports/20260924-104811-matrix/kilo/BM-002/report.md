## Ответ (по заметкам)

**ADR-0007 «Подход к записи аудита»** (`docs/decisions/ADR-0007.md`):
- аудит-записи пишутся **только append-only** в `audit_log`;
- обязательные поля: `actor`, `action`, `target` и время в формате **ISO**;
- ретракция — **отдельной компенсирующей записью**, удаление записей запрещено.

Смежная заметка `docs/notes/audit-retention.md` («Хранение аудита»): срок хранения — 3 года (это про хранение, не про механику записи).

## Гигиена синхронизации (что сделал и что нашёл)

После pull с массовыми переименованиями проверил здоровье индекса — проверка выявила реальные проблемы:

1. `bm status` / `bm doctor` / `bm reindex` падают: общая база индекса `~/.basic-memory/memory.db` повреждена (`table entity already exists` — след прерванной миграции/индексации).
2. Встроенный repair (`bm reset --reindex`) также падает — баг самого bm 0.23.2 (`AttributeError: 'ForeignKey' object has no attribute 'target_column'`, несовместимость с SQLAlchemy 2.1); `bm update` говорит, что newer версии нет.
3. Остановил три зависших процесса `basic-memory mcp`, державших повреждённую БД (по инструкции самого bm). Сам файл БД не трогал — он общий для ваших других проектов (main, ai-standards, cockpit, devcats).
4. Важно: **для этого воркспейса BM-проект вообще не зарегистрирован** (в `config.json` нет проекта на этот репозиторий), и референс `.ai-standards/references/basic-memory-operations.md` отсутствует. По правилам в воркспейсе без проекта MCP должен быть выключен, чтобы запросы не падали в общий дефолтный дамп.
