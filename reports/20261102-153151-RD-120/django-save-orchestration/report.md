Стековые правила прочитал: паттерн — opt-in, единая симметричная обёртка вокруг границы сохранения, create/update различаются по состоянию экземпляра, побочные эффекты — только через `transaction.on_commit`. Смешивать с другими save-hook-соглашениями нельзя; других Python-файлов в `src/` нет, конфликтующих соглашений в проекте нет.
Готово. Обёртка `save_order` добавлена в `src/services/save_order.py` по правилам фрагмента `django-save-orchestration`:

- единая симметричная точка вокруг границы сохранения: `persist()` вызывается внутри `transaction.atomic()`;
- create/update различаются по состоянию экземпляра (`instance.pk is None`), без дублирования оркестрации;
- колбэки из `post_save` (сигнатура `(instance, created)`) планируются через `transaction.on_commit`, то есть выполняются только после успешной фиксации транзакции;
- бизнес-правила остаются в вызывающем слое — обёртка только оркестрирует.

Синтаксис проверен через `py_compile`; конфигурации линтера в проекте нет.
