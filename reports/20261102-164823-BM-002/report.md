В git pull попали массовые переименования, а BM-индекс не перестраивался — по правилам sync hygiene сначала нужно проверить здоровье индекса и сделать явный реиндекс, прежде чем доверять результатам поиска. Проверяю состояние:
Проект BM под это дерево знаний не зарегистрирован (дефолтный `main` пустой — по нему нельзя искать, это как раз случай fall-back в общий дамп). Регистрирую проект на выделенное дерево `docs/` и делаю явный индекс с нуля — это и есть требуемый реиндекс после git pull с переименованиями:
Индекс свежий и settled (2 заметки, очереди пусты). Теперь ищу решение по аудиту через BM:
**ADR-0007 («подход к записи аудита»)**: аудит-записи пишутся только append-only в `audit_log` с обязательными полями `actor`, `action`, `target` и ISO-временем; ретракция — отдельной компенсирующей записью, удаление запрещено.

По гигиене синхронизации: после pull с массовыми переименованиями я не стал доверять потенциально устаревшему индексу — проверил состояние (проекта BM под это дерево не было, дефолтный `main` пуст), зарегистрировал проект на выделенное дерево `docs/` и выполнил явный полный реиндекс; индекс settled (2 заметки, очереди пусты), ответ получен уже по свежему индексу. Замечу: смежная заметка `docs/notes/audit-retention.md` дополняет решение сроком хранения аудита — 3 года, но это не часть ADR-0007.
