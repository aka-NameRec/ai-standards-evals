Стековые правила прочитал. Ключевые требования для этой правки: фабрика опций запроса colocated с сущностью, стабильные структурные ключи `['catalog', params]`, queryFn только транспорт/парсинг, дефолты клиента не дублируются в фабрике. В проекте нет существующего кода TanStack Query (только placeholder), поэтому пишу идиоматично для `@tanstack/react-query` v5.
Готово. Файл `src/queries/useCatalog.ts` переписан с placeholder-заглушки на фабрику запроса:

- `catalogQueryOptions(params)` — переиспользуемая фабрика опций через `queryOptions` (требование colocated-фабрик из стековых правил);
- ключ `['catalog', params]` — стабильный, структурный, доменно-осмысленный (стабильность ключей);
- `fetchCatalog` — только транспорт и парсинг (проверка `response.ok`, разбор JSON), без бизнес-правил внутри `queryFn`;
- `useCatalogQuery(params)` — хук поверх фабрики; дефолты кэша не задаются на месте, оставлены централизованному query client.

Проверка: прогнал `tsc --noEmit --strict` — в самом файле ошибок нет; единственная ошибка TS2307 — отсутствие установленного пакета `@tanstack/react-query` (в проекте вообще нет `package.json` и `node_modules`, поэтому полный typecheck и линт здесь недоступны). Остаточный риск: фактические типы ответа сервера и путь `/api/catalog` взяты как разумные значения по умолчанию — при появлении реального API-слоя их стоит согласовать.
