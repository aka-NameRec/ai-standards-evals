# Решение: пер-скилловый оракул активации для trigger set'ов

Дата: 2026-10-12 · Change set: `STD-CHANGE-0002` · Issue: aka-NameRec/ai-standards#24 (сценарии `TRG-003`)

## Контекст

`run_triggers.py` определял активацию skill'а единым механическим сигналом —
«в ответе агента распознан стандартный code-review-отчёт»
(`report_shape.check`). Для `TRG-003` (навык `autonomous-task-run`) это дало
7 ложных отрицаний из 7 позитивных кейсов: процедура корректно активировалась
(skill-инструмент вызывался, `skill_seen: true` во всех позитивных кейсах),
но её исход — не ревью-отчёт, а исполнение слайсов; форма «What Was Done» в
ответе не появляется. Кроме того, первый легитимный ход процедуры — отказ по
entry gate с запросом недостающего (план утверждён не был в части кейсов) —
отчётом не является по определению.

## Решение

1. Сигнал активации выбирается по типу навыка: отчётные навыки
   (`standard-code-review`, `TRG-001`) — распознавание стандартного отчёта;
   процедурные навыки (`autonomous-task-run`, `TRG-003`) — факт вызова
   skill-инструмента (`skill_invoked`), регистрируемого в потоке событий
   `kilo run --format json`.
2. Реализация: `SKILL_INVOCATION_SETS = {"TRG-003"}` в `scripts/run_triggers.py`;
   наборы без записи в множестве используют отчётный сигнал (обратно
   совместимо с `TRG-001`).
3. Негативный кейс остаётся нарушенным только при фактическом вызове
   skill-инструмента; известно ограничение: компенсаторная загрузка процедуры
   по чужой триггер-фразе (кейс «зафиксируй знания стандартным образом» —
   фраза недеплоированного `capture-knowledge`) даёт false positive при
   поведенчески корректном ответе. Итог прогона 2.8.1 — 10/11, отказ
   зафиксирован честно; нормативная правка (пометка в контракте `TRG-003`
   или заострение negative-space описания навыка) — отдельный поток в
   `ai-standards`.

## Альтернативы

### Поведенческий оракул активации (ветка в фикстуре, task spec в ответе)

Отклонено на этот цикл: поведение первого хода процедурного навыка легитимно
варьирует (исполнение против отказ-by-entry-gate), детерминированного
механического признака «процедура начата корректно» без переусложнения
не видно; требуется отдельная проработка контрактов.

### Единый сигнал «skill_invoked» для всех trigger set'ов

Отклонено: для `TRG-001` вызов skill-инструмента слабее распознавания отчёта
— отчёт является нормативным исходом ревью, и исторические кейсы
ориентированы на него.

## Последствия

- Позитивные кейсы `TRG-003` проходить по факту активации; ложные отрицания
  устранены (7/7 после переноса).
- Один документированный false positive на компенсаторной загрузке остаётся
  (кейс «зафиксируй знания»), 10/11 в прогоне 2.8.1.
- Добавление новых процедурных skill'ов — одна строка в
  `SKILL_INVOCATION_SETS` и fixture builder в `BUILDERS`.
