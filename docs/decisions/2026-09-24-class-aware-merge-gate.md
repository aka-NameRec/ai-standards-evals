# Решение: классы отказов и стабилизация среды в merge-гейте

Дата: 2026-09-24 · Change set: `STD-CHANGE-0001` · Issue: aka-NameRec/ai-standards#22

## Контекст

Merge-гейт сравнивал вердикты сценариев по рангам (PASS/MIXED/FAIL) между
baseline и кандидатом. Языковая модель, исполняющая сценарии, стохастически
допускает осечки оформления отчёта (~7–10 % прогонов): строка версии,
вклеенная в заголовок, разовый сбой порядка секций, неограждённая публикация.
Асимметрия правила («MIXED» у кандидата при «PASS» у baseline = downgrade)
превращала ACCEPT в лотерею: гейт-2 отверг корректное изменение на двух
оформительских осечках, при том что судья по содержанию дал 30/30, а baseline
осекался в тех же классах.

Средовой шум усугублял картину: порождаемые агенты наследовали пользовательские
инструкции оператора (rtk) и тратили усилия на борьбу с ними; за день — два
зависания по 900 секунд без автоповтора.

## Решение

1. Детерминированная таксономия отказов (`scorers/failure_classes.py`):
   недостоверность / оформительские / содержательные; нераспознанные строки по
   умолчанию считаются содержательными. Классификация без участия LLM.
2. Сравнение по классам (`compare_runs.downgrade_reason`): ухудшение — только
   при недостоверности, которой нет у baseline; при содержательных отказах в
   большинстве эпох кандидата при чистом большинстве baseline; либо при
   появлении нового содержательного класса. Оформительские осечки
   фиксируются по эпохам, не блокируют и отслеживаются как тренд.
3. Стабилизация среды: spawn-агенты получают изолированный пустой
   `XDG_CONFIG_HOME` (без пользовательских инструкций оператора); таймаут
   исполнителя перепробуется один раз с пометкой в артефактах.

## Рассмотренные альтернативы

- **Слить со ссылкой на разбор вариации** (ручное одобрение REJECT):
  плохо масштабируется — каждый следующий гейт снова лотерея, а решение
  принимается человеком по десяткам JSON-артефактов.
- **Больше эпох и требование полного PASS**: при вероятности осечки ≈ 0.1 на
  прогон шанс хотя бы одной за 2 эпохи ≈ 19 % на сценарий; с ростом покрытия
  ACCEPT становится недостижимым. Худший вариант.
- **Ослабить скореры** (принимать любую форму): отклонено — форма отчёта
  нормативна (RVW-030), ослабление маскирует реальные деградации. Вместо
  этого расширены только окна рендеринга, уже разрешённые гайдлайнами
  (версия с разметкой заголовка; секции жирными метками).

## Последствия

- Merge-гейт устойчив к росту покрытия и сравнивает то, ради чего существует:
  содержательное поведение.
- Оформительские осечки не исчезают из поля зрения — они в отчёте по эпохам;
  устойчивый оформительский дрейф (как неограждённая публикация CR-010 в
  чистой среде, 2/2) виден как тренд.
- Недостоверность и содержательные классы блокируют безусловно.
- Правила зафиксированы в `docs/scorer-guidelines.md`; тесты:
  `tests/test_failure_classes.py`, `tests/test_compare_runs.py`.
