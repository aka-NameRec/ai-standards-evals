# Решение: ранговая охрана и воспроизводимость для нового содержательного класса

Дата: 2026-10-12 · Change set: `STD-CHANGE-0004` · Дополняет: [Решение: классы отказов и стабилизация среды в merge-гейте](2026-09-24-class-aware-merge-gate.md)

## Контекст

Гейт STD-CHANGE-0003 (кандидат `rules-change/26-implement-issue-26` из
`ai-standards`, baseline `2.8.1-2026-10-11`; 16 сценариев × 2 эпохи, адаптер
kilo, судья 26/26) вернул REJECT по единственной позиции `CR-010`: у кандидата
в одной эпохе из двух появилось содержательное осечение (🟡-находка по файлу
вне ревьюемого диффа — слип охвата), тогда как baseline проваливал этот
сценарий в обеих эпохах оформительским классом (неограждённая публикация).
Ранг сценария при этом улучшился: FAIL → MIXED.

Ветвь (в) правила `compare_runs.downgrade_reason` — «появился содержательный
класс, которого baseline не проявлял ни разу» — срабатывает на любое вхождение
класса, без условия воспроизводимости и без учёта ранга. Три следствия,
проявленные этим случаем:

1. вердикт противоречит собственной метрике ранга: кандидат ближе к чистому
   состоянию, чем baseline, но объявлен регрессией;
2. правило несходимо: union классов монотонно растёт, один записанный слип
   нельзя вымыть дополнительными чистыми эпохами той же ревизии — единственный
   выход из такого REJECT, ручное решение, то самое «плохо масштабируется»,
   против которого написано решение от 2026-09-24;
3. правило слепо к состоянию базовой поверхности: сценарий с baseline FAIL 2/2
   наказывает кандидата так же, как сценарий с чистым baseline, хотя критерий
   гейта — «отсутствие регрессий относительно baseline».

Слип агента стохастичен по природе — как и оформительские осечки; система
рангов (PASS/MIXED/FAIL) существует именно для различения разовой осечки и
систематического поведения.

## Решение

1. Ветвь (в) переопределяется: новый содержательный класс понижает вердикт
   только при выполнении обоих условий — класс воспроизводится (большинство
   эпох кандидата) **и** ранг сценария не улучшился относительно baseline.
2. Единичное содержательное осечение на сценарии с улучшившимся рангом
   записывается и отслеживается как тренд — по тем же основаниям, что и
   оформительская вариация. Сигнал не исчезает из вердиктных данных
   (`verdict.json` хранит отказы всех эпох).
3. Остальные ветви не меняются: недостоверность блокирует безусловно и не
   подчиняется ранговой охране; оформление никогда не блокирует; мажоритарная
   ветвь (б) сохранена дословно.
4. При вызове `downgrade_reason` без рангов сохраняется консервативное чтение:
   неизвестный ранг никогда не считается улучшением.

## Рассмотренные альтернативы

- **Только мажоритарное условие (без ранговой охраны)**: проще, но тонкий
  сигнал (1 слип на 4 эпохи при том же ранге) проходит молча там, где ранг
  не улучшался — ранговая охрана точнее кодирует «регрессию относительно
  baseline».
- **Только ранговая охрана**: систематический класс (2/2) при том же ранге
  ловится, но правило теряет симметрию с мажоритарной ветвью и допускает
  спорный кейс «1/2 при том же ранге» — блокирует только благодаря (б),
  что неочевидно.
- **Ничего не менять**: каждый следующий гейт с 16+ сценариями снова
  лотерея с ненулевым шансом одиночного содержательного слипа; REJECT
  разрешается только ручным решением — отвергнуто решением от 2026-09-24.

## Последствия

- Гейт сравнивает то, для чего существует: регрессию относительно baseline;
  разовые слипы кандидата на улучшающихся сценариях больше не отменяют
  ранговый сигнал.
- Одиночные содержательные слипы остаются видимыми: по эпохам в вердиктных
  данных и как тренд в таблице сравнения.
- Проверка: детерминированные тесты
  `tests/test_compare_runs.py` (кейс CR-010 — не понижает; систематический
  класс при том же ранге — понижает; недостоверность — блокирует и на
  улучшившемся ранге) и перегенерация сравнения STD-CHANGE-0003 по тому же
  корпусу вердиктов: REJECT → ACCEPT, остальные 15 строк без изменений.
- Ограничение: правило сформулировано для рангов PASS/MIXED/FAIL; при
  расширении системы рангов условие «улучшился» пересматривается.
